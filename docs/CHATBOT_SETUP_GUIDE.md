# 카카오 챗봇 시나리오 설정 가이드 (D 옵션 — Quick Reply + slot filling)

> 일반 6자리 숫자 메시지와 연동 코드가 충돌하지 않도록, 챗봇 진입 시 **버튼 메뉴**로
> "그룹 연동" 흐름을 진입시키고, slot filling으로 코드를 받는 방식.
>
> **이 문서는 카카오 i 오픈빌더 실제 UI 용어로 작성**되어 있습니다.

## 0. 사전 준비

| 항목 | 값 |
|---|---|
| 로컬 ngrok 도메인 | `https://visiting-amused-tag.ngrok-free.dev` |
| 로컬 백엔드 포트 | 8081 (SERVER_PORT) |
| ngrok 실행 | `ngrok http --url=visiting-amused-tag.ngrok-free.dev 8081` |
| 카카오 i 오픈빌더 스킬 URL | `https://visiting-amused-tag.ngrok-free.dev/api/v1/chatbot/webhook` |
| 스킬 헤더 | `X-Kakao-Skill-Secret: <KAKAO_SKILL_SECRET>` |

## 1. 시나리오 구조 (변경 후)

```
[웰컴블록]  — 사용중 ON
  ├─ 봇 응답: "안녕하세요..." (텍스트형)
  └─ 바로연결 버튼: [🔗 그룹 연동하기] → 블록 연결 → "그룹 연결"

[그룹 연결 블록]  — 시나리오 01 내, 바로연결 버튼 또는 발화로 진입
  ├─ 필수 파라미터: code 슬롯 (사용자에게 "6자리 코드 입력" 질문)
  └─ 봇 응답: 스킬데이터 사용 (백엔드 webhook)

[폴백 블록]  — 위 어디에도 매칭 안 된 메시지
  ├─ 봇 응답: 스킬데이터 사용 (백엔드 webhook)
  │   → 백엔드가 자동으로 안내 텍스트 + 바로연결 버튼 응답
  └─ (기존 정적 텍스트 응답은 제거)
```

## 2. 카카오 i 오픈빌더 설정 단계

### 2-1. 스킬 URL 변경 (가장 시급 — 1002 에러 해결)

좌측 메뉴 **"스킬"** → 사용 중인 스킬(인스타링크수집 등) 선택 → **URL 필드**:

```
https://visiting-amused-tag.ngrok-free.dev/api/v1/chatbot/webhook
```

→ 저장 → 배포. 이것만 해도 카카오 → 백엔드 호출이 시작됩니다.

### 2-2. "그룹 연결" 블록 정리

시나리오 01 → 그룹 연결 블록 열기.

**(a) 패턴 발화 삭제**

화면 상단 "패턴 발화 (6)" 영역의 등록된 6자리 숫자 모두 **삭제** (`987654`, `123456`, `390042`, `654321`, `000001`, `770285`).

**(b) 새 발화 추가 (바로연결 버튼 진입용)**

"사용자 발화" 영역에서 발화 두 개 추가:
- `그룹 연동하기`
- `🔗 그룹 연동하기`

→ 웰컴 블록의 바로연결 버튼이 이 발화를 발송하면 본 블록이 매칭됨.

**(c) 슬롯 파라미터 만들기**

"파라미터 설정" → **+ 필수 파라미터 추가** 클릭 → "파라미터 만들기" 다이얼로그:

| 필드 | 값 |
|---|---|
| 파라미터 이름 | `code` |
| 엔티티 | **`sys.text`** ← 모든 텍스트 받기 (검증은 백엔드가 처리) |
| 필수 파라미터로 설정 | ✅ 체크 |
| 기본값 사용 | (체크 안 함) |
| 사용자에게 질문 (다음 단계) | `우리가갈지도 앱에서 발급받은 6자리 연동 코드를 입력해주세요.` |
| 다시 묻기 횟수 | 2 (선택) |
| 파라미터 검증 API 설정 | (비워둠 — 백엔드 스킬이 알아서 검증) |

> **왜 `sys.text`인가**: 카카오 표준 `@sys.number`는 숫자 포맷 전반 매칭이라 길이 제약이 없고, `sys.constant`는 미리 등록한 고정값만 매칭됩니다. 백엔드가 어차피 `BotUserMappingService.link()`에서 코드 유효성/만료를 검사하므로, 슬롯은 사용자 입력을 통째로 받는 게 단순하고 안전합니다.

→ **확인** 클릭으로 슬롯 저장.

**(d) 봇 응답 = "스킬데이터 사용"으로 변경**

"봇 응답" 영역에 "+ 응답 추가" → **스킬데이터** 선택 → 사용할 스킬 = 인스타링크수집 (또는 이름 동일한 webhook 스킬).

→ 슬롯이 채워지면 카카오가 `action.params.code`에 사용자 입력을 담아 백엔드로 보냄. 백엔드는 코드를 검증하고 응답.

### 2-3. 웰컴 블록 활성화

좌측 메뉴 → **"기본 시나리오"** → **웰컴 블록**.

**(a) 사용 토글 ON**

상단의 **"미사용 → 사용중"** 토글 클릭. (스크린샷에선 처음엔 미사용, 두 번째에선 사용중)

**(b) 봇 응답 1: 텍스트형**

"+ 응답 추가" → **텍스트** 선택 → 다음 텍스트 입력:

```
안녕하세요! 우리가갈지도 챗봇입니다 🗺️
인스타 릴스 링크를 보내면 자동으로 핀이 등록돼요.
먼저 앱에서 발급한 6자리 코드로 그룹을 연동해주세요.
```

> **줄바꿈**: 실제 입력란에서 Enter 키로 줄바꿈 (`\n` 문자 그대로 쓰지 마세요).

**(c) 바로연결 버튼 추가 (= Quick Reply)**

봇 응답 박스 아래의 **"바로연결 버튼 설정"** 영역 → **+** 클릭 → "바로연결 버튼 설정" 다이얼로그:

| 필드 | 값 |
|---|---|
| 버튼명 | `🔗 그룹 연동하기` |
| 버튼 기능 | **블록 연결** |
| 연결할 블록 | **그룹 연결** (시나리오 01 안의 블록) |

→ 확인 → 웰컴 블록 **저장**.

> "블록 연결"로 설정하면 사용자가 버튼을 누르는 즉시 그룹 연결 블록의 slot filling이 시작됩니다 — "6자리 코드를 입력해주세요" 질문이 노출됨.

### 2-4. 폴백 블록 = 스킬 호출로 변경

좌측 메뉴 → **"기본 시나리오"** → **폴백 블록**.

**(a) 기존 텍스트 응답 삭제 (선택)**

현재 화면처럼 "무엇을 원하는지 잘 모르겠어요" 등 텍스트 응답 3개가 랜덤형으로 등록되어 있다면, 모두 우측 휴지통 아이콘으로 **삭제**. (그대로 두면 백엔드 응답과 같이 랜덤 출력됨 — 메시지 흐름 일관성 위해 삭제 권장)

**(b) 스킬데이터 응답 추가**

"+ 응답 추가" → **스킬데이터** 선택 → 사용할 스킬 = 인스타링크수집 (그룹 연결 블록에서 사용한 것과 동일).

→ 저장.

> 폴백 블록이 스킬을 호출하므로, 사용자가 어떤 메시지(인스타 URL 포함)를 보내든 백엔드가 받아서 처리:
> - 인스타 URL → 자동 핀 등록
> - 일반 메시지 → "🔗 그룹 연동하기" 바로연결 버튼 포함 안내
> - 일반 6자리 숫자 → **위와 동일하게 안내** (더 이상 코드로 오인 X)

### 2-5. (선택) 인스타 URL 전용 별도 블록

폴백 블록이 모든 메시지를 백엔드로 라우팅하므로 별도 블록은 필요 없음.
원하면 시나리오 01 안에 새 블록 `릴스 등록`을 만들어 인스타 URL 정규식 패턴 발화로 분리할 수 있지만, 동작은 동일.

## 3. 저장 후 배포

각 블록 우측 상단 **"저장"** → 좌측 **"배포"** 탭 → **"배포하기"**.

> 배포 안 하면 카톡 챗봇에 반영 안 됨. 시나리오 수정 후 반드시 배포 단계 확인.

## 4. 테스트 시나리오

| 입력 | 기대 동작 |
|---|---|
| 챗봇 친구 추가 직후 | 웰컴 메시지 + `🔗 그룹 연동하기` 바로연결 버튼 노출 |
| `🔗 그룹 연동하기` 버튼 클릭 | "6자리 코드를 입력해주세요" 응답 (slot filling 시작) |
| 코드 (예: `123456`) 입력 | 연동 완료 응답 ("인스타그램 릴스 링크를 보내면 자동으로 장소가 저장됩니다.") |
| 일반 메시지 `안녕` | 폴백 → 안내 + 바로연결 버튼 |
| 일반 6자리 숫자 `987654` (코드 아님) | 폴백 → 안내 + 바로연결 버튼 (이전엔 연동 시도 오류 발생) |
| 인스타 릴스 URL | "메모를 보내주세요" 안내 + 빠른답장 `[❌ 메모 없이 저장]` (1개) — pending 세션 시작 |
| 인스타 URL 직후 임의 텍스트 (메모) | 해당 텍스트를 메모로 함께 자동 핀 등록 |
| 인스타 URL 직후 `[❌ 메모 없이 저장]` 클릭 | 메모 없이 자동 핀 등록 |
| 인스타 URL 직후 1분 무응답 | 백그라운드로 메모 없이 자동 저장. 사용자 다음 발화 응답 앞에 `📌 이전에 보낸 링크는 메모 없이 자동 저장되었어요…` 알림이 1회 prepend (이후 소비) |
| pending 상태에서 새 인스타 URL | 이전 URL은 백그라운드 즉시 자동 저장 → 새 URL은 새 pending 시작. 응답에 "이전 링크는 백그라운드로 저장 중이에요" 안내 포함 |
| 인스타 URL + 일반 메시지 혼용 | URL 추출 가능하면 등록, 안 되면 폴백 안내 |

## 5. 백엔드 변경 요약 (이미 적용됨)

- `MessageClassifier`: `^\d{6}$` 정규식 매칭 제거 → `action.params.code` 기반으로 LINK_CODE 판별
- `LinkCodeHandler`: utterance 무시, `params.code`에서만 코드 추출
- `SkillResponse`: `quickReplies` 필드 지원 추가 (`Template.quickReplies`)
- `ChatbotWebhookService`: 미연동/폴백 응답에 `🔗 그룹 연동하기` 바로연결 버튼 동봉 + 안내 텍스트 명확화
- **인스타 메모 흐름 v2 (2026-05-20)**:
  - pending TTL `chatbot.instagram.pending-ttl-seconds` (기본 180, local/test 30, 단축 검증 시 `CHATBOT_INSTAGRAM_PENDING_TTL_SECONDS=1` 환경변수)
  - QuickReply 1개: label=`❌ 메모 없이 저장`, message=`메모 없이 저장` (정확 매칭만 memo=null 트리거)
  - 취소 분기 완전 제거 — 링크 보낸 이상 저장 보장
  - 시나리오 C/D 백그라운드 자동 저장 + `PendingNotificationSession`(TTL 7일) prepend 알림

## 6.1 메모 흐름 발화 → 블록 라우팅 매트릭스

| 사용자 행위 | 발화 텍스트 | 카카오 라우팅 | 백엔드 결과 |
|---|---|---|---|
| `[❌ 메모 없이 저장]` 클릭 | `메모 없이 저장` | 패턴 매칭 0건 → 폴백 블록 | INSTAGRAM_PENDING_MEMO → memo=null 처리 |
| 메모로 임의 텍스트 입력 | (자유) | 폴백 블록 | INSTAGRAM_PENDING_MEMO → memo=텍스트 저장 |
| 메모로 `그룹 연동하기` 입력 | `그룹 연동하기` | 그룹 연결 블록(발화 패턴 매칭) | LinkCodeHandler → "이미 연동" 응답. **메모 손실** (알려진 한계) |
| 메모로 새 인스타 URL 입력 | `https://...` | 폴백 블록 | MessageClassifier → INSTAGRAM_LINK → D 시나리오 분기 |

## 6.2 운영 배포 전 카카오 시나리오 검증 체크리스트

| ☐ | 항목 |
|---|---|
| ☐ | 폴백 블록이 "스킬데이터 사용"으로 설정 (§2-4 (b)) |
| ☐ | 폴백 블록의 정적 텍스트 응답 모두 삭제 (랜덤 출력 방지) |
| ☐ | 그룹 연결 블록 패턴 발화에 `\d{6}` 형태 모두 삭제 (§2-2 (a)) |
| ☐ | 어느 블록에도 `메모 없이 저장` 패턴 발화가 없음 (시나리오 01 + 기본 시나리오 전체) |
| ☐ | 시나리오 저장 후 **배포** 클릭 |
| ☐ | 실시간 시연: 인스타 URL → `[❌ 메모 없이 저장]` 클릭 → 풀 코스 응답 도달 |
| ☐ | 실시간 시연: 인스타 URL → TTL 무응답 → 다음 발화 시 `📌 이전에 보낸 링크는…` prepend 확인 (local 환경 `CHATBOT_INSTAGRAM_PENDING_TTL_SECONDS=30`으로 단축 검증) |

## 6. 트러블슈팅

| 증상 | 원인 / 해결 |
|---|---|
| 카카오에 "스킬 서버 연결 오류 (1002)" | (a) ngrok 미실행: `pgrep -fl ngrok` 확인. (b) 스킬 URL이 본인 계정 ngrok 도메인 아님: `https://visiting-amused-tag.ngrok-free.dev/api/v1/chatbot/webhook` 인지 확인 |
| 슬롯 채우기에서 "유효하지 않은 값입니다" | "파라미터 검증 API 설정"이 입력된 경우. 비워둘 것 |
| 코드 입력했는데 "연동 코드를 받지 못했어요" | 슬롯 변수명이 `code`가 아님. 그룹 연결 블록의 파라미터 이름 재확인 |
| "이미 연동된 계정입니다" | 같은 카카오 사용자가 이미 다른 앱 계정에 연동됨. 앱에서 그룹 탈퇴 후 재시도, 또는 다른 앱 계정으로 코드 재발급 |
| 바로연결 버튼을 눌러도 슬롯 질문이 안 나옴 | "바로연결 버튼"의 **버튼 기능**이 "블록 연결"인지 확인. "메시지 전송"이면 텍스트가 발화로만 들어가 slot filling이 시작 안 될 수 있음 |
| 인스타 URL이 폴백으로 빠짐 | 정상 — 폴백 블록이 스킬을 호출하므로 백엔드가 URL을 판별해서 핀 등록 처리. 분리하려면 시나리오 01에 인스타 URL 정규식 패턴 발화 블록 추가 |
| `[❌ 메모 없이 저장]` 눌렀는데 다른 응답이 옴 | 그룹 연결 블록 또는 다른 블록에 `메모 없이 저장` 발화 패턴이 등록되어 있을 가능성 — 시나리오 01 + 기본 시나리오 전체에서 해당 패턴 제거. 폴백 블록만 받게 두어야 PendingMemoHandler 로 라우팅됨 |
| 사용자가 메모로 `그룹 연동하기` 텍스트를 보냈더니 연동 응답이 옴 | 알려진 한계 — 카카오 시나리오 매칭이 webhook 호출보다 먼저 일어나 메모가 백엔드에 도달하지 않음. 그 메모만 손실되고 pending 은 그대로 유지되어 1분 후 자동 저장으로 흘러감 |
