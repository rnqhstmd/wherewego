# PRD: D단계 — 알림 상세 보강 / 내정보 축소 / 그룹관리 (IA 재설계 GM-2)

## 배경
IA 재설계 GM-2의 마지막 기능 묶음. A(내비골격)·C(맵)·DM(봇방목록) 이후 **알림·내정보·그룹관리** 3개 화면을 완성한다.
- **알림**: 작성자 닉네임·핀은 표시하나 "어느 그룹"이 빠져 1인 다중 그룹에서 맥락이 불명확.
- **내정보**: 그룹 관리가 지도 상단 `⋯`로 이동 → 내정보의 "활성 그룹" 섹션은 중복.
- **그룹관리**: 지도 `⋯` 진입점·placeholder만 존재. 그룹원 조회·이름수정·삭제·탈퇴 + **방장 개념** 필요.

## 용어
- **방장(owner)**: 그룹 활성 멤버 중 가장 먼저 가입한 사람(`group_members.joined_at` 최소, 동률 시 id 최소). 그룹 생성자가 최초 방장. 방장 탈퇴 시 남은 활성 멤버 중 최선임이 **자동 승계**(별도 owner 컬럼 없이 조회 시점 계산).

## 요구사항

### [Must]
1. **(알림 그룹명)** 백엔드 알림 목록/상세 응답에 `groupName` 추가. iOS 알림 행·상세에 그룹명 표시.
2. **(내정보 축소)** `MyInfoView`의 "활성 그룹" 섹션(그룹명/멤버수/탈퇴) 제거 → 사용자(닉네임 수정)+계정(로그아웃/계정삭제)만 유지.
3. **(그룹관리 진입)** 지도 `⋯` → `GroupManageView`로 교체(현 `groupManagePlaceholder` 대체).
4. **(그룹원 조회)** 모든 멤버가 그룹원 목록 조회. 각 멤버 닉네임 + 방장 뱃지. 백엔드 `GET /groups/{id}/members`.
5. **(그룹명 수정)** 그룹 이름 수정 + 백엔드 API 신규. **권한 = 모든 활성 멤버**. 수정 시 지도 상단·목록 그룹명 갱신.
6. **(그룹 삭제)** **방장만** 가능. 백엔드 `DELETE /groups/{id}`(soft delete, 비방장 403). 삭제 시 그룹 소멸 → 전 멤버 접근 불가.
7. **(그룹 탈퇴)** 모든 멤버 탈퇴 가능(기존 `leaveGroup` 재사용). 방장 탈퇴 시 자동 승계.
8. **(방장 판정)** 백엔드가 활성 멤버 중 `joined_at`(동률 시 id) 최소를 방장으로 계산.

### [Should]
9. **(권한별 UI)** 본인이 방장이면 "그룹 삭제" 노출, 아니면 숨김. 이름수정·탈퇴는 모두 노출.
10. **(방어)** `groupName` 누락(레거시) 시 그룹명 생략하고 기존 표시 유지.
11. **(삭제 재확인)** 그룹 삭제는 `confirmationDialog`로 재확인.

### [Could]
12. **(정렬)** 그룹원 목록 가입 순(방장 최상단).

## 수용 기준 (AC)
- AC-1: 알림 목록/상세에 그룹명 표시(존재 시). 작성자·핀 회귀 없음.
- AC-2: 내정보에 "활성 그룹" 섹션 없음. 닉네임 수정·로그아웃·계정삭제 동작.
- AC-3: 지도 `⋯` → GroupManageView, 그룹원 목록 표시.
- AC-4: 그룹원 목록에서 방장이 뱃지로 구분.
- AC-5: 그룹 이름 수정 시 반영(지도 상단·목록 갱신). 모든 멤버 수정 가능.
- AC-6: 방장만 "그룹 삭제" 노출·실행. 비방장은 UI 미노출 + 백엔드 403.
- AC-7: 방장 탈퇴 시 다음 최선임이 방장이 되어 삭제 권한 획득.
- AC-8: 일반 멤버는 탈퇴만 가능(삭제 불가).

## 비범위
- 그룹별 별명(닉네임은 전역, 내정보 담당)
- 방장 수동 위임(자동 승계만)
- 그룹 삭제 복구/휴지통
- 푸시·실시간 알림 인프라

## 확정된 정책
- **그룹명 수정 권한** = 모든 활성 멤버.
- **그룹 삭제 권한** = 방장만(활성 멤버 중 최선임).
- **방장 승계** = 자동(조회 시점 joined_at 최소 계산, 컬럼·승계 트랜잭션 불필요).
- **그룹 삭제 시 데이터** = 그룹 soft delete. 핀은 그룹 종속이라 함께 접근 불가(기존 탈퇴 정책과 정합).
