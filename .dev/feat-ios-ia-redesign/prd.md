# PRD: DM — 그룹별 봇방 목록 (IA 재설계 GM-2, #105 소비)

## 배경
IA 재설계로 하단 4탭(지도·DM·알림·내정보) 중 **DM 탭**은 현재 단일 봇 채팅 화면(`BotChatView`)을 그대로 띄운다. 그러나 사용자는 **1인 N그룹**(GM-1)을 지원받고, 백엔드는 #105에서 **그룹별 봇 방**(`(owner, group)`당 활성 1개)으로 재구성되어 그룹별 봇 채팅 API를 이미 제공한다(develop 머지 완료).

iOS는 아직 이 그룹별 API를 소비하지 않고 구버전 비그룹 엔드포인트(`/chat/bot/messages`)를 호출한다. 이 단계는 DM 탭을 **그룹별 봇방 목록**(인스타그램 DM 스타일)으로 전환하고, 각 방을 그룹별 봇 채팅으로 연결한다. 릴스 저장 그룹도 "그 방의 그룹"으로 귀속시킨다.

## 목표
- DM 탭 진입 시 **내 활성 그룹별 봇 방 목록**을 보여준다(인스타그램 DM처럼).
- 목록 항목 탭 → **그 그룹의 봇 채팅 방**으로 진입(그룹별 메시지 송수신).
- **인스타식 읽음 표시**: 안 읽은 방(마지막이 봇 메시지 & 미조회)은 굵게 + 강조점.
- 릴스 위저드 저장 시 핀이 **그 방의 그룹**에 저장된다(현재 `myActiveGroup` 추정 → 방 컨텍스트로 정확화).

## 사용자 시나리오
1. 사용자가 하단 **DM 탭**을 누른다 → 내가 속한 그룹들의 봇 방이 목록으로 보인다(그룹명·마지막 메시지 미리보기·시각·안 읽음 표시).
2. 안 읽은 방은 **굵은 글씨 + 강조점**으로 구분된다(읽은 방은 일반 글씨).
3. 방을 탭하면 **그 그룹의 봇 채팅**으로 들어간다. 릴스 링크를 보내면 그 방(=그 그룹)에 저장된다.
4. 방에서 메시지를 보면 **읽음 처리**되고, 뒤로 나오면 목록에서 그 방이 읽은 상태(일반 글씨)로 갱신된다.
5. 아직 봇과 대화한 적 없는 그룹도 목록에 보이며("아직 대화가 없어요"), 탭하면 빈 채팅으로 들어가 첫 메시지로 대화를 시작한다.

## 요구사항

### Must (반드시)
- **FR-1 (DM 목록)**: DM 탭은 `GET /chat/bot/rooms` 결과를 목록으로 표시한다. 각 항목: 그룹명, 마지막 메시지 미리보기, 마지막 시각, 안 읽음 표시. 백엔드는 **내 활성 그룹 전부**를 가입 순으로 내려준다(봇 방 없는 그룹도 가상 항목 포함).
- **FR-2 (인스타식 읽음)**: `unread == true`(마지막이 봇 & 미조회)인 항목은 **굵게 + 강조점**으로, `false`는 일반 표기로 렌더한다.
- **FR-3 (방 진입)**: 항목 탭 → 그 그룹의 봇 채팅 화면으로 push. 화면은 `GET/POST /chat/bot/{groupId}/messages`(그룹별)로 동작한다.
- **FR-4 (그룹별 API 전환)**: iOS `ChatAPI`를 그룹별로 전환한다 — `botRooms()` 추가, `botMessages(groupId:cursor:limit:)`/`sendBotMessage(groupId:text:)`로 변경. 구버전 비그룹 봇 호출(`/chat/bot/messages`) 소비는 제거한다.
- **FR-5 (릴스 저장 그룹 귀속)**: 봇 채팅 VM에 `groupId`를 주입하고, 릴스 위저드 저장(`savePlaceCards`)은 `myActiveGroup()` 추정 대신 **주입된 그 방의 groupId**로 핀을 저장한다.
- **FR-6 (읽음 갱신)**: 백엔드는 방 메시지 조회(GET) 시 읽음 처리한다. 따라서 DM 목록은 **진입 시점 + 방에서 복귀 시점 + 포그라운드 복귀 시점**에 재조회하여 읽음 상태를 최신화한다.
- **FR-10 (DM 탭 미읽음 배지)**: 안 읽은 봇 방이 하나라도 있으면(`rooms` 중 `unread == true` 존재) 하단 DM 탭 아이콘 우상단에 빨간 점을 표시한다(알림 탭과 동일 패턴, 건수 미표시). 배지 상태는 DM 목록 VM이 보유하고 탭 진입 전에도 관찰 가능해야 한다(알림 배지 패턴 동치). **[확정 — 사용자 승인 2026-06-08]**

### Should (권장)
- **FR-7 (빈/로딩/에러 상태)**: 그룹 0개면 "참여 중인 그룹이 없어요" 안내, 로딩 중 표시, 조회 실패 시 재시도 가능한 에러 표시.
- **FR-8 (미리보기 발신자 표기)**: 마지막 메시지가 사용자(USER)면 "나: …", 봇(BOT)/시스템이면 그대로 미리보기 텍스트를 표시한다. 마지막 메시지 없으면 "아직 대화가 없어요".
- **FR-9 (방 타이틀 그룹 컨텍스트)**: 봇 채팅 화면 타이틀에 **그룹명**을 노출하여 어느 그룹 방인지 식별 가능하게 한다(기존 "어디가지 봇" 단독 → 그룹명 반영).

## 비즈니스 규칙 (BR)
- **BR-1 (활성 그룹 기준)**: 목록은 백엔드가 결정하는 "내 활성 그룹"을 그대로 따른다. iOS는 정렬/필터를 임의로 바꾸지 않는다(가입 순 그대로).
- **BR-2 (가상 항목 진입)**: 봇 방이 아직 없는 그룹(roomId=null) 항목도 탭하면 빈 채팅으로 진입하며, 첫 전송 시 백엔드가 방을 lazy 생성한다.
- **BR-3 (페이지/길이 계약 보존)**: 메시지 페이지 limit·2000자 가드 등 기존 봇 채팅 계약은 그대로 유지한다(그룹별 경로로만 이동).
- **BR-4 (읽음 시맨틱 일치)**: "안 읽음"의 정의는 백엔드 판정(`마지막이 BOT & lastRead < latest`)을 그대로 신뢰한다. iOS는 자체 읽음 계산을 하지 않는다.
- **BR-5 (멤버십 오류)**: 비멤버 그룹 방 접근은 백엔드가 403(GROUP_NOT_MEMBER)으로 막는다 — iOS는 목록에 없는 방을 임의 진입시키지 않으므로 정상 흐름에서 발생하지 않으나, 발생 시 안내 후 목록으로 폴백한다.

## 수용 기준 (AC)
- **AC-1**: DM 탭 진입 시 활성 그룹별 봇 방이 목록으로 표시된다(봇 방 없는 그룹은 "아직 대화가 없어요"로 포함). 그룹 0개면 빈 상태 안내.
- **AC-2**: `unread == true` 항목은 그룹명/미리보기가 굵게 + 강조점이 보이고, `false`는 일반 표기다.
- **AC-3**: 항목 탭 → 그 그룹 봇 채팅 진입. 메시지 송수신이 `/chat/bot/{groupId}/messages`로 이루어진다(구버전 비그룹 호출 없음).
- **AC-4**: 방에서 메시지를 본 뒤 뒤로 나오면, 목록에서 그 방이 **읽은 상태(일반 표기)**로 갱신된다.
- **AC-5**: 그 방에서 릴스 위저드로 장소를 저장하면, 핀이 **그 방의 그룹**에 저장된다(다른 활성 그룹이 아님).
- **AC-6**: 로딩/에러/빈 상태가 각각 구분되어 표시되고, 에러는 재시도할 수 있다.
- **AC-7**: 기존 봇 채팅 동작(전송 후 PROCESSING 버블·폴링 결과 반영·2000자 가드·저장 결과 카드·"지도에서 보기")이 그룹별 방에서 동일하게 동작한다(회귀 없음).
- **AC-8**: 단위 테스트가 갱신/추가되어 통과한다 — `ChatAPIProtocol` 시그니처 변경 반영, 봇 VM groupId 주입, DM 목록 VM(로드/읽음/빈·에러) 신규.
- **AC-9**: 안 읽은 봇 방이 1개 이상이면 하단 DM 탭 아이콘에 빨간 점이 보이고, 모두 읽으면(또는 목록 갱신 후) 사라진다.

## 범위 외 (Non-goals)
- 커플 1:1 방(데드코드)·커플 API 변경. (봇 방만 그룹별로 전환)
- 봇 결과 푸시(APNs)의 그룹별 방 딥링크 정밀 라우팅(현 `.chat` → DM 목록 진입 유지). 그룹 특정 방 자동 오픈은 후속.
- 백엔드 변경(이미 #105로 그룹별 API 제공·머지 완료).
- D 단계(알림 상세/내정보 축소/그룹관리 ⋯), IC-2(초대 코드).
