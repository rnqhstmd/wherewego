# PRD: Phase 5 — iOS 채팅(봇 방 + 1:1 커플방) + 푸시 + 제출 자산

## 배경

P1(백엔드 인증 확장)·P2(채팅·푸시·계정 삭제)·P3(iOS 골격·인증·온보딩)·P4(지도·핀·사진·방문감지)가 develop에 모두 머지된 상태. 백엔드에는 봇 방·커플방 REST(`/api/v1/chat`), STOMP 실시간(`/topic/chat/bot/{userId}`, `/topic/chat/couple/{groupId}`), 디바이스 등록(`/api/v1/devices`) API가 이미 운영 중이다.

현재 iOS 앱은 지도·핀 기능까지 동작하나, 채팅 화면이 없어 핵심 가치(릴스 → 장소 저장, 커플 대화)가 미동작이다. 앱스토어 제출을 위한 Privacy Manifest·권한 문구·리뷰어 데모 계정·앱 아이콘/스플래시도 미비하다.

## 목표

- 봇 채팅방과 1:1 커플방을 iOS 네이티브로 완성하여 두 방·푸시·딥링크가 동작하는 상태 달성
- 앱스토어 심사 제출에 필요한 자산을 완비하여 P6(디자인 정합성 최종 QA) 즉시 착수 가능하게 함
- 성공 기준: 리뷰어가 데모 계정으로 봇 방·커플방·푸시·딥링크를 직접 확인 가능

## 대상 사용자

- **일반 사용자**: 인스타 릴스 링크로 장소를 저장하고 파트너와 대화하는 커플
- **앱스토어 리뷰어**: 데모 계정으로 앱 전체 기능을 검증하는 Apple 심사자

## 요구사항

### 기능 요구사항

**봇 채팅방 (BotChatView)**

- [Must] FR-1: 로그인 사용자별 전용 봇 채팅방을 제공한다. 파트너의 봇 방과 분리되며 크로스포스트 없음.
- [Must] FR-2: 메시지 목록을 최신순(id DESC)으로 cursor 기반으로 로드한다. 기본 20건, 최대 50건. 이전 메시지는 위로 스크롤 시 cursor를 이용해 추가 로드한다(`GET /api/v1/chat/bot/messages?cursor=&limit=`).
- [Must] FR-3: 텍스트 입력 → 전송 시 `POST /api/v1/chat/bot/messages`를 호출하고, 즉시 PROCESSING 버블(로딩 표시)을 화면에 표시한다.
- [Must] FR-4: STOMP(`/topic/chat/bot/{userId}`) 구독을 유지하여 봇이 장소 추출을 완료하면 PLACE_CARDS 메시지를 실시간으로 수신·렌더링한다. PROCESSING 버블은 PLACE_CARDS 수신 시 교체된다.
- [Must] FR-5: PLACE_CARDS 메시지는 장소 후보 카드 목록으로 렌더링한다. 각 카드는 장소명·주소를 표시하고, 버튼(actionPayload) 탭으로 다중 선택·저장이 가능하다.
- [Must] FR-6: 릴스 URL을 입력하면 봇이 처리를 시작한다(FR-3 동일 흐름). 인스타 미디어 원본(이미지·영상)은 서버에 저장하지 않으며 URL 텍스트만 봇 방에 전달한다(App Store Review Guideline 5.2.2 대응).
- [Should] FR-7: MEMO_PROMPT 메시지 수신 시 메모 입력 안내 버블을 표시하고, 사용자가 텍스트를 입력하면 해당 메모를 전송한다.
- [Should] FR-8: SYSTEM 메시지(시스템 안내·오류)는 중앙 정렬 안내 문구 스타일로 렌더링한다.

**1:1 커플방 (CoupleChatView)**

- [Must] FR-9: 그룹(커플)당 하나의 커플방을 제공한다. 봇이 개입하지 않으며 두 파트너 간 텍스트 대화만 가능하다.
- [Must] FR-10: 메시지 목록을 cursor 기반으로 로드한다(`GET /api/v1/chat/couple/{groupId}/messages?cursor=&limit=`). FR-2와 동일 페이지네이션 정책.
- [Must] FR-11: 텍스트 입력 → 전송 시 `POST /api/v1/chat/couple/{groupId}/messages`를 호출한다. 전송 즉시 낙관적으로 내 메시지를 버블에 표시한다.
- [Must] FR-12: STOMP(`/topic/chat/couple/{groupId}`) 구독을 유지하여 파트너 메시지를 실시간으로 수신·렌더링한다.

**공통 채팅 UX**

- [Must] FR-13: 두 채팅방 모두 빈 상태(메시지 0건)일 때 방에 맞는 안내 문구를 표시한다. 봇 방: "릴스 링크를 입력해보세요", 커플방: "파트너에게 첫 메시지를 보내보세요".
- [Must] FR-14: 메시지 버블은 발신자(나/상대/봇)를 시각적으로 구분한다(좌우 정렬 또는 색상).
- [Should] FR-15: 채팅방 진입 시 자동으로 가장 최신 메시지 위치로 스크롤한다.
- [Should] FR-16: 키보드 표시 시 입력창이 키보드 위로 올라온다(SwiftUI 키보드 회피).

**APNs 푸시 + 딥링크**

- [Must] FR-17: 앱 최초 실행 시 푸시 알림 권한을 요청한다. 허용 시 APNs 디바이스 토큰을 `POST /api/v1/devices`에 등록한다(platform: IOS). 기존 토큰이 다른 사용자에게 등록된 경우 서버가 재배정(reassign) 처리한다.
- [Must] FR-18: 로그아웃 또는 계정 삭제 시 `DELETE /api/v1/devices/{deviceToken}`으로 디바이스 토큰을 해제한다.
- [Must] FR-19: 푸시 알림을 탭하면 해당 대상으로 앱 내 딥링크 이동이 이루어진다. 봇 방(BOT_RESULT)·커플방(COUPLE_MESSAGE)은 해당 채팅방으로, PIN_SAVED는 payload에 핀 식별자가 없으므로 지도/핀 목록으로 이동한다. 대상이 삭제된 경우 최상위 화면(지도)으로 폴백한다. (※ design-critic 검증: PushPayload상 PIN_SAVED는 roomId·pinId 미포함)
- [Must] FR-20: Universal Links(`applinks:<도메인>`)로 초대 링크·핀 딥링크를 처리한다. AASA 파일이 웹 도메인에 호스팅되어 있어야 한다.
- [Should] FR-21: 앱이 포그라운드 상태에서 푸시를 수신하면 인앱 배너(알림 말풍선)를 표시한다.

**제출 자산**

- [Must] FR-22: Privacy Manifest(`PrivacyInfo.xcprivacy`)를 앱 타깃과 Mapbox·Kakao SDK 번들에 포함한다. 수집 API(위치·카메라·사진) 및 사용 목적을 선언한다.
- [Must] FR-23: Info.plist에 푸시 권한 외 모든 런타임 권한 문구 3종을 추가한다. `NSLocationWhenInUseUsageDescription`(방문 감지), `NSCameraUsageDescription`(사진 촬영), `NSPhotoLibraryUsageDescription`(사진 접근).
- [Must] FR-24: 앱 아이콘(AppIcon) 및 스플래시(LaunchScreen) Assets 카탈로그를 완성한다. 디자인 레퍼런스(context/design-chats/chat1.md 및 디자인 토큰)를 기반으로 개발자가 임시 버전을 생성하여 1024×1024를 포함한 모든 필수 해상도를 채운다. 최종 에셋 교체는 P6 범위이며 P5를 차단하지 않는다.
- [Must] FR-25: 리뷰어 데모 계정(커플 그룹 1쌍)을 백엔드에 생성하고, 다음 시드 데이터를 포함한다: 봇 방 대화 3건(릴스 URL → PLACE_CARDS 카드 수신 흐름 1회 포함), 핀 3건(태그 혼합 권장), 커플방 메시지 3건. App Store Connect ▸ App Review Information에 계정 자격증명과 진입 방법을 기재한다.
- [Must] FR-26: LoginView에 숨은 데모 로그인 진입점을 구현한다. 앱 로고를 5회 연속 탭하면 "데모 로그인" 버튼이 노출되며, 탭 시 데모 계정으로 자동 로그인된다. 일반 사용자에게는 보이지 않으며 App Store Connect 리뷰어 안내문에 진입 방법을 명시한다. 데모 계정 자격증명은 소스코드에 하드코딩하지 않는다(환경 변수 또는 빌드 설정으로 주입).
- [Should] FR-27: 릴스 URL 처리 흐름 내에 인스타 콘텐츠 방어를 명시한다. 미디어 파일(이미지·영상)을 앱 서버에 저장하지 않고 URL 텍스트만 전달함을 코드 주석 또는 내부 문서에 기록한다(App Store Review Guideline 5.2.2 대응).

### 비즈니스 규칙

- [Must] BR-1: 봇 방은 유저별(per-user) 분리. 한 파트너의 봇 방에 다른 파트너가 접근하거나 메시지를 읽을 수 없다. STOMP 구독 시 서버가 `userId` 일치 여부를 검증한다(`/topic/chat/bot/{userId}`).
- [Must] BR-2: 커플방은 그룹당 하나. 두 파트너만 접근 가능. STOMP 구독 시 서버가 그룹 멤버 여부를 검증한다(`/topic/chat/couple/{groupId}`).
- [Must] BR-3: 봇 방 텍스트 입력 최대 2,000자. 커플방 텍스트 입력 최대 1,000자. 초과 시 전송 불가 처리(입력창 카운터 표시 또는 전송 버튼 비활성화).
- [Must] BR-4: 메시지 페이지네이션 limit은 1~50 범위. 미전달 시 기본 20. cursor는 메시지 id(1 이상 정수); null이거나 1 미만이면 최신부터 조회.
- [Must] BR-5: 봇 방과 커플방 간 크로스포스트 없음. 파트너 핀 저장·커플방 새 메시지 알림은 APNs 푸시로만 전달.
- [Must] BR-6: 릴스 URL 처리 시 인스타 미디어 원본(이미지·영상)을 앱 서버에 저장하지 않는다. URL 텍스트만 봇 방에 전달한다.
- [Must] BR-7: 리뷰어 데모 계정 자격증명은 소스코드에 하드코딩하지 않는다. App Store Connect에만 기재하며, 코드 주입은 환경 변수 또는 빌드 설정을 사용한다.
- [Must] BR-8: STOMP 연결 끊김 시 재연결 정책을 다음과 같이 적용한다. 포그라운드 복귀 시 즉시 1회 재연결 시도, 실패 시 5초 간격으로 최대 3회 재시도(총 4회). 3회 모두 실패 시 채팅방 상단에 "연결 끊김" 상태를 표시하고 수동 재시도 버튼을 제공한다. 재연결 성공 시 REST(`GET /api/v1/chat/*/messages` — cursor=null로 최신 재조회)로 메시지를 재조회하고 클라이언트가 id 기준 중복을 제거하여 미수신분을 반영한다. (※ 백엔드 cursor는 과거 방향(`id < cursor`) 페이지네이션이므로 "최신 보완"은 cursor=null 재조회로만 가능. 끊긴 동안 limit(최대 50)을 초과해 쌓인 분은 상단 스크롤 loadMore로 보완된다.)
- [Should] BR-9: 푸시 권한을 거부한 사용자에게는 재요청 프롬프트 없이 앱이 정상 동작한다. 실시간 수신은 STOMP로만 유지되며 앱 내 기능 제한이 없다.

### 품질 기대

- [Should] QE-1: 채팅방 진입~첫 메시지 표시까지 사용자가 로딩을 기다린다고 느끼지 않는 수준의 응답성.
- [Should] QE-2: STOMP 연결 상태(연결 중·연결됨·재연결 중·연결 끊김)를 채팅방 UI에서 사용자가 인지할 수 있어야 한다.
- [Should] QE-3: 데모 계정 시드 데이터는 봇 방 대화 3건(릴스→PLACE_CARDS 1회 포함)·핀 3건·커플방 메시지 3건을 포함하여, 리뷰어가 핵심 기능(장소 카드 선택, 커플 대화, 푸시 딥링크)을 직접 확인할 수 있는 완성 상태여야 한다.

## 사용자 시나리오

**정상 흐름 — 봇 방에서 릴스 → 장소 카드 선택**

1. 사용자가 봇 채팅방 진입 → 기존 메시지 목록 로드(cursor 없음 → 최신 20건)
2. 인스타 릴스 URL 입력 → 전송
3. 내 메시지 버블 + PROCESSING(로딩) 버블 즉시 표시
4. STOMP(`/topic/chat/bot/{userId}`)로 PLACE_CARDS 수신 → 장소 카드 목록 렌더링, PROCESSING 버블 교체
5. 사용자가 장소 카드 1개 이상 탭(다중 선택) → 저장 확정
6. 파트너 기기에 APNs 푸시 발송(파트너 핀 저장 알림)

**정상 흐름 — 커플방 대화**

1. 사용자가 커플방 진입 → 기존 메시지 로드
2. 텍스트 입력 → 전송 → 내 버블 낙관적 표시
3. 파트너 기기에 APNs 푸시 도착(커플방 새 메시지)
4. 파트너가 푸시 탭 → 앱이 커플방으로 딥링크 이동
5. STOMP(`/topic/chat/couple/{groupId}`)로 파트너 메시지 실시간 수신

**정상 흐름 — 리뷰어 데모 로그인**

1. LoginView에서 앱 로고를 5회 연속 탭
2. "데모 로그인" 버튼 노출
3. 탭 시 데모 계정으로 자동 로그인
4. 봇 방(대화 3건·PLACE_CARDS 포함)·커플방(메시지 3건)·핀(3건) 시드 상태로 진입

**예외 흐름 — STOMP 연결 끊김**

1. 네트워크 단절 또는 앱 백그라운드 전환
2. 포그라운드 복귀 시 즉시 1회 재연결 시도
3. 실패 시 5초 간격, 최대 3회 추가 재시도
4. 총 4회 모두 실패 → 채팅방 상단 "연결 끊김" + 수동 재시도 버튼 표시
5. 재연결 성공 → REST로 미수신 메시지 보완 조회 후 목록 갱신

**예외 흐름 — 딥링크 대상 삭제**

1. 푸시 알림 탭 또는 Universal Link 진입
2. 대상(방/핀)이 삭제된 경우 → 지도 메인 화면으로 폴백

**예외 흐름 — 메시지 전송 실패**

1. 네트워크 오류로 `POST /api/v1/chat/*/messages` 응답 실패
2. 낙관적으로 표시된 버블에 전송 실패 상태 표시
3. 재시도 탭 → 동일 메시지 재전송

**엣지 케이스**

- 빈 채팅방(메시지 0건): 봇 방 "릴스 링크를 입력해보세요" / 커플방 "파트너에게 첫 메시지를 보내보세요" 안내 문구 표시
- PLACE_CARDS 수신 전 앱 백그라운드 전환 후 복귀: 재연결 후 REST 보완 조회로 카드 표시
- 두 채팅방 간 빠른 탭 전환: 각 방의 STOMP 구독이 독립적으로 유지
- 봇 방 2,001자 초과 입력: 전송 버튼 비활성화 또는 전송 차단
- 커플방 1,001자 초과 입력: 전송 차단
- 릴스 URL 검증 실패(URL 형식 아님): 봇이 폴백 메시지("어느 곳인가요?") 반환, 앱은 SYSTEM 버블로 표시
- 디바이스 토큰 재발급(iOS 토큰 교체): 기존 토큰을 해제하고 신규 토큰 upsert. 서버의 reassign 정책 적용
- 푸시 권한 거부: 채팅은 STOMP 실시간으로만 동작. 앱 기능 제한 없음. 재요청 프롬프트 없음
- 앱 아이콘 임시 버전 상태로 빌드: P5에서 전 해상도 채움(비차단), P6에서 최종 교체
- Universal Links AASA 파일 미호스팅: 딥링크 미작동. P5 완료 전 웹 도메인에 AASA 배포 필수

## 영향 범위

- **기존 기능**: P4까지 완성된 지도·핀·온보딩 기능에 영향 없음. 채팅 탭/진입점 추가만.
- **기존 사용자**: P5는 iOS 전용이므로 웹 사용자에게 영향 없음. 백엔드 변경 없음(P2에서 완료).
- **하위 호환성**: 디바이스 토큰 등록은 additive. 기존 웹 알림 폴링 방식에 영향 없음.

## 제외 범위

- 봇 방·커플방 간 메시지 크로스포스트 — 확정 결정으로 영구 제외
- 채팅 이미지·파일 전송 — 텍스트 전용, 차기 고려
- 읽음 확인 표시 — 커플방 상대 읽음 여부 UI 미포함
- STOMP 브로커 이중화(Redis Pub/Sub) — 인메모리 단일 인스턴스 유지, 차기 과제
- App Store 스크린샷·메타데이터·개인정보처리방침 URL 작성 — P6 범위
- 앱 아이콘·스플래시 최종 에셋 교체 — P6 범위(P5는 임시 버전으로 비차단)
- 디자인 정합성 최종 대조(웹↔앱 픽셀) — P6 범위
- Android 대응 — 계획 없음
