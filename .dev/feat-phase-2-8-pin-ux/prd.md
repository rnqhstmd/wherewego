# PRD: Phase 2.8 — 핀 도메인 UX 완성

## 배경

현재 핀 도메인은 CRUD 기능은 갖추고 있으나, 사용자 가시 범위에서 3가지 UX 공백이 존재한다.

| 항목 | 현재 상태 |
|------|----------|
| 웹 직접 등록 시 `instagramUrl` 입력 불가 | 항상 `null`로 저장됨. 챗봇 경로만 `instagramUrl`이 채워지며, UNIQUE 중복 차단은 `null ≠ null` 특성으로 웹 등록에선 작동하지 않음 |
| 장소 정보(장소명/주소) 수정 불가 | `PinEditDialog`와 `PinUpdateCommand` 모두 memo/tag만 지원. 잘못 등록된 장소명을 수정할 방법이 없음 |
| 지도 팝업에서 삭제 불가 | `PinPopup` ⋮ 메뉴는 태그/메모 2뷰만 존재. 삭제는 `/pins` 목록 화면으로 이동해야만 가능 |

Phase 2.8은 위 3가지를 해소하여 핀 도메인의 사용자 가시 UX를 완성한다. 삭제 핀 복원 기능은 이번 Phase 범위에서 제외하며 별도 Phase에서 결정한다.

---

## 목표

- 웹 등록 핀도 챗봇 등록 핀과 동일하게 `instagramUrl` 기반 중복 방지가 작동한다
- 사용자가 잘못 입력한 장소명/주소를 직접 수정할 수 있다
- 지도에서 핀을 보는 중에 삭제까지 완료할 수 있다 (화면 전환 불필요)

## 사용자 시나리오

### ① instagramUrl 입력 — 검색 선택 흐름

1. 사용자가 지도에서 검색 → 장소 선택
2. 태그/메모 입력 패널 하단에 "Instagram URL (선택)" 입력 필드 노출
3. URL 입력 → `https://` 미시작 시 즉시 "올바른 URL 형식이 아닙니다" 메시지 표시, 등록 버튼 비활성
4. URL을 입력하지 않거나 지우면 → `null`로 정규화 → 등록 완료

**예외:** 동일 그룹 내 이미 등록된 `instagramUrl` 입력 후 등록 시도 → "이미 등록된 장소예요" 오류 표시 (Q3 결정 — 단일 메시지)

### ① instagramUrl 입력 — 십자선 picker 흐름

1. 사용자가 ⊕ 버튼으로 crosshair 모드 진입 → 지도 이동으로 위치 선택 → "완료" 클릭
2. 태그/메모/instagramUrl 입력 단계로 이동
3. 검색 선택 흐름과 동일한 입력 필드 패널에서 instagramUrl 입력 가능

### ② 장소 정보 수정

1. 사용자가 `/pins`에서 특정 핀 "편집" 클릭
2. 기존 태그/메모 필드에 더해 "장소명", "주소" 텍스트 편집 필드 추가 표시
3. 장소명 수정 후 저장 → 카드에 즉시 반영 (낙관적 업데이트)

**예외:** 장소명을 공백만으로 저장 시도 → 저장 버튼 비활성, "장소명을 입력하세요" 메시지 표시

### ③ 지도 팝업 삭제

1. 사용자가 지도에서 마커 클릭 → 팝업 열림
2. ⋮ 클릭 → 상단에 "태그 / 메모" 세그먼트 탭 표시. 탭 영역과 시각적으로 구분된 위치에 "삭제" 텍스트 버튼 노출
3. "삭제" 클릭 → 확인 모달 표시 ("이 핀을 삭제할까요?" + 장소명)
4. 확인 → 마커 즉시 제거 + 팝업 닫힘
5. 모달에서 "취소" 또는 닫기(ESC) → 삭제 미실행, ⋮ 펼침 상태 유지

**예외(서버 오류):** 서버 오류 시 마커 복원 + 팝업 내 인라인 에러 메시지 표시

## 비즈니스 규칙 상세

| 상황 | 처리 방식 |
|------|----------|
| instagramUrl = 빈 문자열 | `null`로 정규화 저장. 중복 검사 미수행 |
| instagramUrl = 유효한 URL, 동일 그룹 중복 | `PLC_DUPLICATE_PIN` 에러 → "이미 등록된 장소예요" (Q3 — 단일 메시지) |
| instagramUrl = `https://` 미시작 | 클라이언트 즉시 검증. 등록 버튼 비활성 |
| placeName = 공백만 (trim 후 길이 0) | 클라이언트에서 저장 버튼 비활성 |
| placeName 길이 > 200자 | 클라이언트에서 저장 버튼 비활성 |
| address = 빈 문자열 또는 미입력 | `null` 허용 |
| 지도 팝업 삭제 — 활성 멤버 아님 | `GROUP_NOT_MEMBER` 에러 → 팝업 내 "권한이 없습니다" 표시 |

## 엣지 케이스

| 상황 | 처리 |
|------|------|
| 검색 흐름에서 instagramUrl 중복 등록 시도 | "이미 등록된 장소예요" 인라인 표시 (Q3) |
| 십자선 picker에서 주소 로딩 중 완료 클릭 | 주소 null 허용. 좌표는 항상 존재하므로 등록 가능 |
| 장소명을 공백만으로 저장 시도 | 클라이언트 trim 후 빈 문자열이면 저장 버튼 비활성 |
| 장소명 200자 초과 | 클라이언트에서 저장 버튼 비활성, 글자 수 카운터 표시 |
| 지도 팝업 삭제 중 권한 만료(그룹 탈퇴) | `GROUP_NOT_MEMBER` 에러 → 팝업 내 "권한이 없습니다" 표시, 마커 복원 |
| 확인 모달을 닫고(ESC/취소) 다시 "삭제" 클릭 | 팝업 상태 초기화 없이 재진입. 삭제 미실행 이력 없음 |
| ⋮ 펼침 중 다른 마커 클릭으로 핀 전환 | 팝업 뷰 및 펼침 상태 초기화 (기존 `trackedPinId` 패턴 동일 적용) |
