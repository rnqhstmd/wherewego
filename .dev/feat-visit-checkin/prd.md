# PRD: 방문 체크인·추억 전환 정책 v2

- 작성: 2026-06-12 (gx-dev requirements phase)
- SSOT: `context/pin/visit-checkin-policy.md` (2026-06-12 확정)
- 브랜치: feat/visit-checkin (base: develop — #125 핀 패리티·.pinFocus / #126 PIN_REPLY 채팅 카드 인프라 포함)

## 1. 배경

현행(Phase 10)은 "방문자 1인이 '네 다녀왔어요' 확인 → 즉시 MEMORY 전환 + VISIT_DETECTED 알림 fan-out"이다. 커플(2인) 전제의 설계라, 다인 그룹에서는 **개인의 위치 이벤트가 그룹 공유 자산(핀 태그)을 변경**하는 모순이 생긴다 — 한 명이 혼자 들렀다 전환하면 나머지 멤버의 위시가 소멸하고, 안 가본 사람에게도 "추억"이 된다.

단, 주 유입(릴스 공유→장소 등록)이 발견/위시만 쌓는 구조라 **전환 시스템 자체는 필수**이며, "전원 방문" 조건은 비현실적이므로 **일부 멤버만 함께 가도 추억이 될 수 있어야** 한다.

> 확정 정책: **혼자 간 건 체크인, 둘 이상 함께 간 건 추억. "함께"는 방문자가 선언하고, 방문 기록은 union으로 누적되며, 누구와의 추억인지가 핀에 남는다.**

## 2. 요구사항

### 백엔드

- **[Must] FR-B1 방문 기록 저장소**: `pin_visits(pin_id, user_id, visited_at, source SELF|TAGGED)` 테이블 신설(마이그레이션 V023). `(pin_id, user_id)` 유니크 — upsert 시 `visited_at` 갱신, `TAGGED` 행에 본인 체크인이 오면 `SELF` 승격(역방향 강등 없음).
- **[Must] FR-B2 체크인 API**: 혼자 방문 선언 — 핀 태그 **변경 없음**(위시 보존), `pin_visits`에 본인 `SELF` upsert. 그룹 활성 핀 검증(soft-delete·타그룹 핀 거부).
- **[Must] FR-B3 추억 전환(동행 선언)**: 본인 포함 2명 이상의 동행 명단으로 호출 → WISH/REEL→MEMORY 전환은 **1회·멱등**(이미 MEMORY면 태그는 그대로 두고 visits만 **union 합산**), 본인 `SELF`·타인 `TAGGED` upsert. 응답에 `alreadyConverted` 구분(클라 합산 토스트용). 동행 명단은 그룹 활성 멤버만 허용.
- **[Must] FR-B4 핀 응답에 방문자 합류**: 핀 조회 응답에 `visitors[]`(userId·닉네임·프로필 이미지 URL — GP-1 프사 resolver 선례) 포함. 방문자 0명이면 빈 배열. 추가형 계약(구 클라이언트 호환).
- **[Must] FR-B5 채팅 카드 자동 전송**: **발신 주체 = 방문자**(서버가 방문자 명의로 자동 적재 — 프사+닉네임 표시, PIN_REPLY 선례).
  - 체크인 카드: "다녀갔어요 📍" — **무푸시**(채팅방 적재만).
  - 추억 카드: "함께 다녀왔어요 🎉" + **동행 아바타 스택**(텍스트 명단 없음) — **푸시 발송**(기존 그룹 채팅 푸시 경로).
  - 핀 카드 탭→지도 딥링크, (추억 핀 사진 존재 시) 사진 제자리 펼침 — PIN_REPLY 버블과 동일.
- **[Must] FR-B6 VISIT_DETECTED 완전 폐기**: 알림 생성 경로(`createForVisitDetected`·`NotificationVisitWriter`) 제거 + **마이그레이션으로 과거 VISIT_DETECTED 행 DELETE** + 백엔드 응답 매핑·iOS 렌더 분기 코드 제거. 그룹 공유는 채팅 카드가 담당.

### iOS

- **[Must] FR-I1 동행 선택 시트**: 도착 감지(현행 엔진·100m·30초·MEMORY 제외·세션 중복 방지 그대로) 시 기존 VisitToast 대신 "○○에 도착! 누구와 함께인가요?" 시트 — `🙋 혼자예요` / 그룹 멤버 다중 선택(본인 자동 포함, 본인 외 1명 이상 선택 시 동행). "나중에요" 닫기 유지.
- **[Must] FR-I2 혼자 플로우**: 체크인 API 호출 → 핀 태그 유지 + 확인 토스트. MEMORY 전환·confetti·메모 시트 없음.
- **[Must] FR-I3 동행 플로우**: 전환 API 호출 → confetti + "다녀온 흔적" 시트(기존 VisitMemoSheet 재사용).
- **[Must] FR-I4 이미 전환됨 처리**: `alreadyConverted` 응답 시 "△△님이 이미 추억으로 남겼어요 🎉 회원님의 방문도 기록했어요" 토스트(전환 UI 생략, 방문 기록은 union 합산됨).
- **[Must] FR-I5 방문자 아바타 스택**: 핀 말풍선(보기 모드) 장소 행 아래 겹친 프사 스택(그룹 목록 memberStrip 문법, 18pt·-5 오버랩) + "N명이 다녀감". 0명이면 행 자체 생략.
- **[Must] FR-I6 1인 그룹 예외**: 그룹 멤버가 본인뿐이면 "혼자예요"도 MEMORY 전환(현행 동작 보존 — 회귀 없음).
- **[Must] FR-I7 채팅 방문 카드 렌더**: 체크인/추억 카드 버블 — 방문자 프사+닉네임 발신, 추억 카드는 동행 아바타 스택 포함. 핀 카드 탭=`.pinFocus` 딥링크, 추억 핀 사진 제자리 펼침(PIN_REPLY 버블 선례).

## 3. 비범위 (구현하지 않음 — 확정)

- 오입력 정정("나 안 갔어요" 제외 기능)·동행 확인 알림 — **베타 수용**. 수렴 장치는 본인 체크인 승격 + 채팅 카드 공개 + 태그 수동 편집뿐.
- 웹(frontend) 반영 — 앱 게시 시 종료 예정.
- 방문 이력 화면(타임라인) 등 신규 화면.

## 4. 엣지 판정

| 엣지 | 판정 |
|---|---|
| 동시 제출(둘 다 작성) | 멱등+union — 늦은 제출도 손실 없음, 합산 토스트(FR-I4) |
| 선언 불일치 A=[A,B]·B=[B,C] | union [A,B,C], C는 TAGGED(도착 시 SELF 승격) |
| 재방문 | 위시 유지 핀은 재감지 발동(세션 단위 중복 방지 현행 유지). 그때 동행 선언으로 전환 가능 |
| 다른 멤버 화면의 떠 있는 시트 | 전환 후 폴링/reconcile로 핀이 MEMORY 되면 자동 소멸(현행 규칙) |
| 탈퇴 멤버의 visits | 행 잔존, 아바타는 GP-1 프사 resolver 규칙 따름(탈퇴=폴백 표시) |
| 핀 삭제 | 기존 soft-delete 규칙 — visits 행 잔존(핀 미노출이므로 표시 경로 없음) |

## 5. 수용 기준

- **AC-1**: 다인 그룹에서 "혼자예요" 선택 시 핀 태그가 변경되지 않고, 그룹 채팅에 방문자 명의 체크인 카드가 적재된다(푸시 없음).
- **AC-2**: 멤버 2명 이상 선언 시 WISH/REEL 핀이 MEMORY로 전환되고 confetti+흔적 시트가 뜨며, 채팅에 추억 카드(아바타 스택 포함)가 적재되고 그룹원에게 푸시된다.
- **AC-3**: 같은 핀에 두 멤버가 연달아 동행 선언해도 전환은 1회, 두 명단의 union이 `pin_visits`에 남고, 늦은 쪽은 합산 토스트를 받는다.
- **AC-4**: TAGGED로 적재된 멤버가 본인 체크인하면 SELF로 승격된다(중복 행 없음).
- **AC-5**: 핀 말풍선에 방문자 아바타 스택+"N명이 다녀감"이 표시된다(0명이면 미표시).
- **AC-6**: VISIT_DETECTED 알림이 더 이상 생성되지 않고, 과거 행도 마이그레이션으로 삭제되며, 알림 탭에 노출되지 않는다(기존 IT 개편 포함).
- **AC-7**: 1인 그룹에서는 "혼자예요"가 MEMORY 전환으로 동작한다.
- **AC-8**: 비활성 핀·타그룹 핀·비멤버 포함 동행 명단은 400으로 거부된다.

## 6. Q&A 확정 사항

- Q1 채팅 카드 발신 주체 → **방문자 발신**(서버 자동 생성, 프사+닉네임)
- Q2 푸시 → **추억 카드만 푸시**, 체크인 카드 무푸시
- Q3 과거 VISIT_DETECTED → **마이그레이션 DELETE + 렌더 코드(백엔드·iOS) 제거**
- Q4 추억 카드 동행 표시 → **아바타 스택만**(텍스트 명단 없음)
