# PRD: 내비 셸 재구성 — 2탭 하단바 + 상단 그룹 전환 칩 (Hotfix)

## 배경
현재 iOS 앱은 하단 FloatingTabBar에 **지도 / 채팅 / 알림 / 내정보** 4탭을 배치한다. 백엔드가 멀티그룹(한 유저가 여러 그룹 동시 소속)을 지원하게 됐으나, iOS 앱은 단일 활성 그룹(`myActiveGroup()`)만 취급하며 그룹 전환 경로가 없다. 확정 IA: 하단바는 그룹 종속 탭(지도/채팅) 2개만 유지하고, 상단바에 그룹 전환 칩·알림·내정보를 배치한다.

## 목표
- 유저가 상단 칩 한 번으로 소속 그룹을 전환하고, 지도(핀)·채팅(방)이 즉시 전환된 그룹 기준으로 갱신된다.
- 알림·내정보는 그룹 전환과 무관하게 전역 접근 가능하다.
- 기존 4탭에서 2탭+상단바로 전환하며 어떤 기능도 누락되지 않는다.

## 요구사항

### 기능
- **[Must] FR-1**: 하단 FloatingTabBar를 **지도 / 채팅 2탭**으로 재구성. `MainTab` enum에서 `notification`, `myInfo` 제거.
- **[Must] FR-2**: 지도·채팅 화면 상단에 **TopBar**(좌: 그룹 전환 칩, 우: 알림 버튼 + 내정보 버튼).
- **[Must] FR-3**: **그룹 전환 칩** — 활성 그룹명 표시, 탭 시 `GroupSwitcherSheet`.
- **[Must] FR-4**: `GroupSwitcherSheet` — `GET /api/v1/groups`(`listMyGroups`) 목록 표시, 항목 탭 시 전환, 하단 "그룹 추가/만들기".
- **[Must] FR-5**: **전환 시 즉시 동기화** — 활성 그룹 변경 시 지도(핀 재로드)·채팅(방 전환)을 해당 그룹으로 즉시 갱신. 전환 전 데이터 폐기.
- **[Must] FR-6**: `GroupAPI.listMyGroups()` 추가 (`GET /api/v1/groups` → `[GroupSummaryResponse]`).
- **[Must] FR-7**: `MapViewModel`이 외부 주입 groupId로 로드 가능하도록 변경. 전환 시 새 groupId로 재로드.
- **[Must] FR-8**: **알림 버튼**(TopBar 우측) — 탭 시 `NotificationInboxView` **시트**. 미읽음 배지=전역 합산(`unreadCount > 0`).
- **[Must] FR-9**: **내정보 버튼**(TopBar 우측) — 탭 시 `MyInfoView` **시트**. 그룹 전환과 무관.
- **[Should] FR-10**: TopBar는 `WGColor`/`liquidGlass*` 토큰으로 기존 화면과 통일.
- **[Could] FR-11**: 전환 시트에서 현재 활성 그룹에 선택 표시.

### 비즈니스 규칙
- **[Must] BR-1**: 그룹 1개여도 칩 탭 가능, 시트에 "그룹 추가/만들기" 노출. 자동 스킵 안 함.
- **[Must] BR-2**: 그룹 0개 — 칩 "그룹 없음", 시트엔 "그룹 만들기"만. 지도·채팅 빈 상태 유지.
- **[Must] BR-3**: 미읽음 배지 = 전역 합산(`NotificationInboxViewModel.unreadCount`). 그룹별 분리는 범위 밖.
- **[Must] BR-4**: 어디갈까(🎲)는 활성 그룹 컨텍스트, 지도 우상단 시트 현행 유지. 전환 시 열려 있으면 닫고 전환.
- **[Must] BR-5**: 알림·내정보는 시트 진입. 기존 탭 네비게이션 폐기.
- **[Should] BR-6**: `listMyGroups()`는 시트 진입 시 호출(앱 시작 시 미리 로드 X). 로딩 중 스피너.
