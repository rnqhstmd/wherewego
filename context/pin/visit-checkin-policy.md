## 배경 — 왜 바꾸는가

Phase 10의 자동 전환은 커플(2인) 전제였다: "내가 갔다 ≈ 우리가 갔다". 다인 그룹에서는 **개인의 위치 이벤트가 그룹 공유 자산(핀 태그)을 변경**하는 모순이 생긴다 — 한 명이 혼자 들렀다가 전환하면 나머지 멤버의 위시가 소멸하고, 안 가본 사람에게도 "추억"이 된다.

단, **전환 시스템 자체는 필수**다 — 주 유입(릴스 공유→장소 등록)이 발견/위시만 쌓는 구조라, 전환이 없으면 추억이 생기지 않는다. 또한 "전원 방문" 조건은 다인 그룹에서 비현실적(일정이 안 맞음)이므로 **일부 멤버만 함께 가도 추억이 될 수 있어야** 한다.

## 확정 정책 (한 줄)

> **혼자 간 건 체크인, 둘 이상 함께 간 건 추억. "함께"는 기계가 판정하지 않고 방문자가 선언하며, 방문 기록은 union으로 누적되고, 누구와의 추억인지가 핀에 남는다.**

## 플로우

```
도착 감지(방문자 폰 온디바이스, 현행 100m·30초·MEMORY 제외 규칙 유지)
  ↓
"○○에 도착! 누구와 함께인가요?" 시트
  ├─ 🙋 혼자예요
  │     → 체크인만: 핀 태그 유지(위시 보존)
  │       + pin_visits 적재(SELF) + 채팅 핀 카드 "○○님이 다녀갔어요 📍"
  └─ 🧑‍🤝‍🧑 멤버 선택(본인 포함 2명 이상)
        → MEMORY 전환(1회·멱등) + confetti + "다녀온 흔적" 시트(사진/메모, 기존 재사용)
          + 동행 visits 적재(본인 SELF, 타인 TAGGED)
          + 채팅 추억 카드 "셋이서 ○○ 다녀옴 🎉"(사진 펼침 가능 — #126 카드)
```

## 규칙 상세

1. **도착 프롬프트는 방문자에게만** — 온디바이스 감지라 구조적으로 그 장소에 있는 멤버에게만 뜬다. 그룹 공유는 **채팅 핀 카드가 담당**(기존 `VISIT_DETECTED` 알림 탭 항목은 채팅 카드로 대체·폐기 — 중복 제거).
2. **체크인 = 개인 기록, 충돌 없음** — `pin_visits(pin_id, user_id, visited_at, source)` upsert. 재방문은 visited_at 갱신.
3. **추억 전환 = 멱등 + union 합산** — 동시 제출 시 태그 전환은 선착 1회, 늦은 제출자의 동행 정보는 visits에 **합산**되고 "△△님이 이미 추억으로 남겼어요 🎉 회원님의 방문도 기록했어요" 토스트. 늦게 누른 멤버가 잃는 것 없음(수정 권한 문제 자체가 없음).
4. **출처 구분** — `source = SELF`(본인 폰 체크인) / `TAGGED`(타인이 동행 선언). 표시는 동일(아바타 스택), 내부 수렴 로직 전용: TAGGED 멤버가 나중에 본인 도착 체크인하면 SELF 승격.
5. **오입력(예: 아직 안 온 멤버를 동행에 포함) = 베타 수용 (확정)** — 별도 "나 안 갔어요" 제외 기능·동행 확인 알림 **구현하지 않는다**. 수렴 장치는 ① 본인 체크인 승격 ② 채팅 카드 명단 공개(사회적 검증) ③ 태그 수동 편집(말풍선 편집 모드)뿐. 그룹 내부 기록이라 피해 반경이 작다.
6. **재방문 = 재감지** — 혼자 체크인으로 위시가 유지된 핀은 다음 방문에 감지가 다시 발동(중복 방지 shownPinIds는 세션 단위, MEMORY 제외 규칙 그대로). 그때 멤버 선택으로 전환.
7. **아바타 스택 = 방문 이력 union** — "추억의 동행"과 "예전에 혼자 다녀간 사람"을 구분하지 않는다. 핀 말풍선(보기 모드) 장소 행 아래 겹친 프사 스택(그룹 목록 memberStrip 문법, 18pt·-5 오버랩) + "N명이 다녀감". 채팅 핀 카드에도 노출 가능.
8. **예외** — 1인 그룹은 "혼자예요"도 전환 허용(함께의 최소 단위=본인). 2인 그룹은 상대 1명 선택 = 기존 동작과 사실상 동일(회귀 없음).
9. **수동 변경은 항상 가능** — 태그는 말풍선 편집 모드에서 언제든 전환/되돌리기. 감지는 보조 수단.

## 엣지 판정표

| 엣지 | 판정 |
|---|---|
| 혼자 방문 | 체크인만 — 위시 보존, 그룹 위시 소멸 문제 해소 |
| 일부 멤버만 함께 방문 | 추억 전환 OK — 동행 명단이 핀에 남아 "누구와의 추억"인지 맥락 보존. 못 간 멤버는 나중에 가면 체크인 합류 |
| 동시 제출(둘 다 작성 중) | 멱등+union — 늦은 제출도 정보 손실 없음(규칙 3) |
| 선언 불일치(A=[A,B], B=[B,C]) | union [A,B,C]. C는 TAGGED — 곧 도착하면 SELF 승격, 오입력이면 베타 수용(규칙 5) |
| 같은 장소 다른 멤버의 떠 있는 토스트 | 전환 직후 폴링/reconcile로 핀이 MEMORY가 되면 자동 소멸(현행 규칙) |
| 핀 삭제/그룹 탈퇴 | 기존 soft-delete·멤버십 규칙 따름(visits는 FK cascade 또는 잔존 — 구현 시 결정) |
