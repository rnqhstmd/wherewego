# tag

핀의 카테고리. **Phase 2.14에서 3종으로 확장**: REEL(발견) / WISH(설렘) / MEMORY(추억). 지도에서 파스텔톤 마커로 시각화된다.

## 태그 정의

| enum | 표시명 | 등록 경로 | 아이콘 | 색상 |
|------|--------|-----------|--------|------|
| `REEL` | **발견** | 카카오톡 챗봇 → 인스타 릴스 자동 등록 | 인스타그램 스타일 파스텔 아이콘 (둥근 정사각형 + 렌즈) | 연보라 `#C5B4E3` |
| `WISH` | **설렘** | 웹 직접 등록 — 가보고 싶은 곳 | ● 동그라미 | 민트 `#A8E6CF` |
| `MEMORY` | **추억** | 웹 직접 등록 — 다녀온 의미 있는 곳 | ♥ 하트 | 핑크 `#FFB3C6` |

## 배경

MVP에서는 PLACE / MEMORY 2종으로 출발했으나, PLACE 하나가 "릴스에서 발견한 곳"과 "내가 직접 저장한 가보고 싶은 곳" 두 의도를 혼재시켜 지도 맥락이 불명확했다. Phase 2.14에서 PLACE를 REEL(발견)과 WISH(설렘)로 분리해 등록 경로와 사용자 의도를 1:1로 대응시킨다. MEMORY(추억)는 유지.

PRD §3-B의 `visited` UI는 tag 도입과 함께 **제거**되었고, REEL→WISH→MEMORY의 자연스러운 장소 여정을 태그로 표현한다.

## 안 하면 어떻게 되는가

- 릴스 자동 등록과 내가 저장한 위시리스트가 같은 색으로 섞여 지도 가독성 저하
- "왜 이 핀이 있지?"라는 맥락 손실 → 사용자가 핀 의미를 기억에 의존해야 함

## 사용자와 규모

- 모든 MVP 사용자가 사용 (~100명, 핀당 1태그 강제)
- 비율 추정: 챗봇 자동 등록 비중이 높아 REEL 60% / WISH 15% / MEMORY 25% 예상

## 성공 기준

- 챗봇 자동 등록 시 `REEL` 기본값 정확도 100%
- 웹 직접 등록 시 WISH / MEMORY 선택 UI (REEL는 웹 등록 불가, 챗봇 전용)
- 지도에서 3종 마커 시각 구분 즉시 인지 가능
- 룰렛 후보 풀: REEL + WISH (발견·설렘 모두 아직 안 간 곳), MEMORY 제외 기본
